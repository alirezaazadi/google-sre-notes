Appendix F — Example Production Meeting Minutes

The example production minutes demonstrate the recurring feedback loop described in the communication chapter: review the error budget, action items, outages, pages, silences, planned changes, resource trends and SLOs, then assign new work. It is deliberately a service-health meeting, not a personal status meeting.

01 — start with state

The meeting begins from unresolved production reality

The example announces a major outage that exhausted the error budget and immediately reviews previous action items.

This creates continuity between meetings; reliability work is not forgotten when the incident chat closes.

02 — outage

Connect the incident to engineering decisions

The Shakespeare outage review records 1.21B lost queries and the interaction between a latent file-descriptor leak, a missing new sonnet, and unprecedented traffic.

Follow-up work includes load balancing and load shedding, and the exhausted error budget freezes normal pushes for a month unless an exception is granted.

That is exactly how SLO policy becomes visible in routine engineering management.

03 — pages

Review whether alerts deserve human attention

The example alert AnnotationConsistencyTooEventual paged five times and was believed to reflect replication delay without an imminent fix.

The team raises the acceptable threshold from 60s to 180s to reduce unactionable alerts while continuing investigation.

This is not 'make the dashboard green'; it is an explicit decision that the old threshold created pager work without a matching urgent action.

04 — planned changes

Give future risk a shared context

The team records an upcoming USA-1 cluster maintenance window and explicitly notes that no manual response is expected because traffic should route automatically.

Resources borrowed during the incident are also reviewed so emergency capacity is returned rather than silently becoming permanent overprovisioning.

05 — SLO + resources

Put user health beside saturation

Resource trends show CPU 60%, RAM 75%, disk 44%, with previous-week comparisons.

Key service metrics show p99 latency 88 ms against a <100 ms target, but availability 86.95% against a 99.99% target.

Seeing user-level SLO status and resource state together helps the team distinguish a reliability breach from a capacity trend.

06 — close with ownership

Every discussion should produce trackable action

New action items name an owner for raising the alert threshold and another for returning borrowed resources.

Minutes therefore become the interface between weekly observation and actual engineering execution.
